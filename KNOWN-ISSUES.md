# v3.1 local preview — no publication

The local batch includes the retained Peek/chooser fixes, v1-style launches, solved-screen fitting, constant-width boards by default (Mode B; Mode A retained), moderately stronger haptics and three CC0 music tracks. The user’s conditional permission was used to prepare a **local** v3.1 service-worker cache after feature completion. The old live site, all backups and the shipped v3 tar are unchanged. Screenshot review/approval is still required before any live update.

- Real iPhone/Safari/WebKit and Galaxy S24 hardware, physical vibration intensity, hardware mute behavior, notches and audible output quality remain **unverified**. Chromium tests include actual local audio playback/decoding plus policy mocks, not human listening or a physical handset.
- Tracks were selected from source descriptions (calm acoustic guitar/flute/strings), not by imitating or using Timberborn material. Subjective musical fit needs Sebastián's listening review. Author/source pages assert CC0; no independent provenance audit can prove an uploader's ownership beyond those license declarations. Source HTML and hashes are retained.
- MP3 fallback and offline Range responses are automated in Chromium. Actual older-iOS decoding, audio interruptions and home-screen audio lifecycle still need device testing. A browser may require a fresh gesture to resume interrupted audio; failures stay silent and the next gesture retries.
- Music defaults on only after interaction, at low gain; Relax lowers it further rather than muting it. Sound effects and Music are separate controls. Clearing site data also clears these preferences.
- v6 folder exists but has no approved spec/approval marker; **not integrated**. Current starter PNGs are unchanged. Celebratory soaking uses a CSS lower-edge fade over the existing cutouts, not new poses/art.
- Default **Mode B** prioritizes constant near-full-width boards (reference ratio 97.2222%), so 5×5 cells are deliberately larger again despite the earlier preference. A single `GAME_CONFIG.boardSizingMode` switch retains Mode A (target 52px cells / growing board). At 360px B seven-column cells are **44.28px** minimum, not 48px, which cannot fit with the retained frame/gaps. At 412px they are **51.50px** minimum. All board targets remain ≥44px at both tested widths; widths below 360px are outside this verified matrix. See the measured table and A/B screenshots in `reports/ROUND-v3.1.md`.

# Known issues / honest limits — v3

- Real iPhone/Safari and Galaxy S24 hardware, vibration strength, OS install prompts and physical notches are **unverified**. Automated iOS checks emulate platform values in Chromium, not WebKit. Viewport/touch tests are 412×915 plus solved-layout / board sizing at 360×780, scale 1.
- Localhost install/offline and actual v1→v3 / v2→v3 service-worker upgrades are tested. No live site was changed. This box-only server is not a link a phone can access.
- All progress is device-local localStorage; no accounts/cloud sync/export UI. Browser eviction/clearing can erase it. Future schemas are read-only; unavailable storage warns.
- Daily content is a deterministic finite 365-board bank per eligibility state, with eight transforms. Human difficulty/playtest quality is not proven by the proof-effort metric.
- Peek is intentionally a one-cell solution ghost, not the old always-available logical Hint. Bloom/Remy normal-mode powers provide defense, not guidance; Relax converts them to Peek by default.
- The supplied v5 example includes fixed Doze and wearable accessory concepts. These new mechanics are not added to the unchanged verified campaign; old cast selection maps to a starter and original ID is retained. Earned boss progress becomes the spring's persistent decoration milestones. No wearable accessory editor/UI is implemented.
- Hot Spring crew uses the supplied composed scene (all three starters visibly half-submerged); changing starter changes badges/labels/hit target, not the scene's character order. Jun/Remy chooser previews use a CSS pond with their supplied cutouts; Bloom uses supplied stage art.
- English only. No comprehensive assistive-technology audit. Keyboard cell/control operation and reduced motion are tested; mobile touch targets and clipping are checked at the target viewport. Active games can use scrollable fallbacks on shorter screens; solved screens are explicitly non-scrolling at both requested sizes. This is not an exhaustive device matrix.
- A service-worker update activates a new cache atomically; an already-open old UI must reload to run new modules. UI notifies when a fresh pond is ready.
