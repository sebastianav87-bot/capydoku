## 4. Scoring + optional leaderboard (added 18:27 ET, approved by Sebastián)
### Pond score (local, `score.js`, pure + unit-tested)
`score = (1000 + 200 × orangesLeft + timeBonus) × helpFactor × roleFactor`, rounded to an integer.
- **timeBonus** = round(500 × (target − t) / target) when t < target, else 0. It is never negative; t is the pond's play time in seconds.
- **Logic target times:** 7×7 180 s · 8×8 240 s · 9×9 330 s · 10×10 420 s.
- **orangesLeft (logic):** the 0–3 regular oranges left at the finish. The crate spare orange is not counted.
- **helpFactor:** 0.5 if Show me (crate) or Second chance (logic) was used in that attempt, otherwise 1.
- **roleFactor:** ×1.5 for bosses and crate ponds, otherwise 1.
- **Crate ponds** have no oranges, so they use an "orange equivalent" from moves vs par: ≤ par → 3; ≤ 1.25 × par → 2; ≤ 1.5 × par → 1; otherwise 0. Their target time is max(60, 1.5 s × par moves).
- **Daily Pond** is not scored (it is not part of a world).
- **Best per pond** is stored as `progress.scores[id] = {best, at}`; replays can only raise it. World score = the sum of the best pond scores in that world (30 ponds).
- **Migrated saves** have no score data. Those ponds show "—" / "unscored, replay to score" and add 0 to the world score until they are replayed.
- **UI:**
  - the solved summary shows the pond score (and "New best");
  - Settings › Progress shows each world's score (scored ponds n/30);
  - on a world change (after the world gate at 30/60/90/120/150) a "World k complete" screen shows the top 10 + the player's rank.
### Leaderboard client (`leaderboard.js`)
- **Opt-in only** (Settings › Leaderboard):
  - optional nickname (default "Anonymous capy", max 16 chars, filtered);
  - a random player id (not personal); no other data;
  - a privacy notice ("we send only your nickname, a random id and your world scores");
  - "Leave and delete" removes the nickname, the id and the queue, and asks the backend to delete the player's entries.
- **Offline first:** local scores are always kept. Uploads (best world scores) are queued in localStorage and flushed with retry/backoff on `online`, on start and after each solve, and only while opted in.
- **Backend (decided 18:39 ET): Cloudflare Workers Free + D1** (LEADERBOARD-OPTIONS.md). Code in /workspace/capydoku/worker/
  (Worker, schema.sql, wrangler.toml template with placeholder ids, README with deploy steps). **Not deployed; no account, login or Cloudflare call.**
- **Adapter contract = the Worker API** (worlds 1-based on the wire): `join({player_id, nickname})`, `score({player_id, world, score, ponds})`,
  `leaderboard(world, player_id)`, `optOut(player_id)`. Player id = UUID v4 (crypto.randomUUID).
  - `http` (the Worker via fetch) is used only when `GAME_CONFIG.leaderboardApi` is an https URL; **it is '' in v5.0 → off**.
  - `mock` (same contract, localStorage DB) is the default for tests (`?lb=mock` / localStorage hook); `none` otherwise → local-only view.
  - Registration (join) is sent before the first score and again after a nickname change; a permanently rejected score (4xx) is dropped;
    a leave that can't reach the server is retried later (pendingOptOut).
- **Server checks:** totals ≤ world max (72 450) and optional pond breakdown within pond caps and summing to the total; best-only upsert;
  D1 fixed-window rate limits per salted-IP hash and per player; CORS only for ALLOWED_ORIGIN; opt-out deletes the player and scores.
- **Worker tests:** handler logic on a node:sqlite D1 stand-in, plus the real Worker in workerd via Miniflare with a local D1 (no account needed);
  the app's client tests run the client against the Worker handler too.
- Without opt-in, offline, or with the `none` adapter, the top-10 screen shows a local-only view: the player's world score and a note.
- **Tests:**
  - unit: formula + edge cases, queue/backoff, adapter contract;
  - E2E: opt-in flow with the privacy notice and leaving/deleting, offline queueing then flush, the world-change top-10 screen.
